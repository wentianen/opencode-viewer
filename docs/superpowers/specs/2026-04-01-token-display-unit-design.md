# Token Display Unit 设计文档

日期：2026-04-01

## 目标

优化 Viewer 中 token 消耗的显示单位，让大数值更容易快速阅读，同时不丢失精确值。

本次改动只处理 token 数显示，不调整 cost、session 数或 message 数的格式。

## 当前问题

当前界面直接显示完整 token 数值。

这在数值较大时存在两个问题：

- 扫读成本高，尤其是时间线与会话统计区域
- 顶部概览、会话统计、时间线都在显示 token，但缺少统一的紧凑展示规则

## 影响范围

本次统一以下三个展示位的 token 文案：

- 顶部 `UsageOverview`
- 左侧 `SessionTree` 中的 session stats
- 时间线 `Timeline` 中记录级 token 标签

## 方案比较

我们讨论过三种方案：

1. 只保留完整数字，加千分位分隔
2. 只在顶部概览使用紧凑单位，其他位置保持完整数字
3. 全部统一为紧凑单位，同时保留完整数字作为补充信息

最终选择方案 3，因为它同时满足可读性与精确性，也能避免同一产品内出现多套 token 展示规则。

## 选定方案

前端新增一个统一的 token 格式化工具，所有 token 展示位都通过它输出文案。

展示规则如下：

- `< 1000`：显示原值，例如 `950`
- `>= 1000 && < 1_000_000`：显示 `K` 单位，保留最多 1 位小数，例如 `1234 -> 1.2K`
- `>= 1_000_000`：显示 `M` 单位，保留最多 1 位小数，例如 `1250000 -> 1.3M`
- 若小数部分为 0，则去掉尾零，例如 `1000 -> 1K`

补充规则如下：

- 所有紧凑 token 文案都保留完整数字作为补充信息
- 补充信息通过 `title` 属性暴露，例如 `1,234 tokens`
- 时间线仍使用紧凑单位加短标签的形式，但 hover 后能看到完整值

## 实现边界

本次不引入新的后端字段，不修改聚合逻辑，不改动 API 契约。

只在 Web 层新增格式化函数并替换现有 token 文案拼接逻辑。

## 测试要求

需要覆盖以下行为：

- 普通值保持原样，例如 `950`
- 千级与百万级正确转为 `K` / `M`
- 尾零被移除，例如 `1.0K -> 1K`
- 顶部概览、会话统计、时间线都使用统一格式
- 对应元素保留完整 token 数字的 `title`
